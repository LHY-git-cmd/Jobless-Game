## 运行与维护

先在专用环境完成Flyway V1～V9，再按顺序开启 `PROGRESSION_ENABLED`、`COSMETICS_ENABLED`、`PK_ROOMS_ENABLED`、`MATCHMAKING_ENABLED`，默认全部关闭。Docker与服务器配置示例已同步；既有本地或生产配置未被自动改写，未启动/替换现有站点。新入口位于首页底部，旧游戏、榜单和练习入口继续使用原行为。

Nginx仅对 `/api/v1/me/events`关闭缓冲和缓存、读取超时75秒；普通API保留短超时。SSE每账号一条、全局16条、每队列16条且单事件≤2KiB，最长60秒重新鉴权；流不持数据库连接，慢客户端在有界期限内关闭。API仍一个worker、320MiB/1CPU、DB池3/执行槽4，房间4个、等待票8张。部署前必须核对这些参数与其他服务的实际占用。

可复现命令详见 `backend/README.md`。容量观测脚本 `python -m backend.probe_pk_capacity`只读普通API/SSE，默认30分钟，需要专用测试会话文件和另行准备的对局/排队。报告不包含Cookie，不会自行标记目标机容量通过。正式历史清理脚本需明确项目库并备份后按需调用。
