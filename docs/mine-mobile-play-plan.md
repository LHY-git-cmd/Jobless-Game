# 扫雷手机操作与结算优化计划

日期：2026-10-25（北京时间）。用户已确认棋盘、下一关及重开行为。

## 需求与边界

- 移除游戏面板中的图标、规则和音效快捷区，音效仍由共享设置管理。
- 压缩游戏顶部及统计区间距。10×10棋盘按可用宽高适配，大棋盘保留44px格子和区域滚动。
- 重新开始使用醒目按钮。踩雷后无需等待爆炸动画或二次确认即可重开；进行中仍确认，体力及幂等规则复用现有接口。
- 胜利改为原生dialog弹窗，显示保存状态和实际奖励，提供返回选关与下一关；保存失败可重试，保存成功前不进入下一关。
- 下一关按入门、简单、中等、困难、地狱排列，同难度按棋盘面积从小到大；最后一关返回选关。
- 打开共享设置暂停当前扫雷，关闭后解除该暂停原因；标签隐藏、离页、退出确认等独立暂停原因继续有效。
- “还差排查格数”计算未揭开的安全格，标旗不减数，踩雷不扣安全格。

## 技术选型声明

沿用原生HTML/CSS/JavaScript、原生dialog与服务端现有计时、结算、重开接口。最高优先级是让常见手机竖屏下的10×10棋盘及操作可见，同时保持踩雷后立即重开的能力。只调整扫雷；共享设置仅新增开关事件，其他游戏不订阅即可保持原行为。不新增依赖或数据库迁移。

验收发现现有后端重开白名单遗漏lost状态，会拒绝踩雷后的重开。补充该状态并复用已有账号行锁、体力事务与幂等逻辑；保留原失败记录。已先补充真实踩雷的API测试并观察到attempt_terminal失败，再修复。上线必须同步重建后端镜像，前端补丁单独覆盖不足以实现快速重开。

## 实施步骤

1. 先添加安全格计数、下一关顺序和棋盘尺寸回归测试，观察失败。
2. 修改扫雷布局、通关弹窗、立即重开和共享设置暂停；保留账号隔离、请求失败重试和暂停叠加逻辑。
3. 用独立Chrome和临时SQLite先复现旧版不满足的界面，再验证320/375/430px竖屏、横屏、爆炸中重开、结算断网重试、返回/下一关、设置与后台暂停。
4. 更新说明、目录树及受影响的样式基线；运行相关测试，按功能用中文提交。

## 验收限制

手机浏览器地址栏及内嵌浏览器会改变可用高度，尺寸计算使用visualViewport并监听变化。极短横屏及大棋盘允许滚动，不能以缩到无法点选保证任意尺寸整屏显示。测试使用本机隔离数据，不改服务器账号、不自动部署。
