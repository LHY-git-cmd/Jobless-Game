# 前端模块化重构计划

日期：2026-10-21（北京时间）。状态：用户已在聊天确认实施；六阶段代码与本地验收完成，分阶段中文提交。实际统计和环境待验收见 [实施报告](./frontend-refactor-report.md)。

## 技术选型与范围

沿用多页 HTML、原生 JavaScript ES Module、FastAPI 与已有 Nginx 部署方式。
最高优先级是固定现有行为与状态归属，再拆分入口。保持页面地址、游戏规则、旧存档格式、账号隔离、绝对计时起点和幂等请求负载。
本次不迁移 SPA、不增加构建工具、常驻服务或数据库迁移。

## 执行顺序

1. 建立现有前端测试基线，检查测试初始化方式和部署路径。
2. 统一 Docker、宝塔模板与本地 FastAPI 的 HTML/JS/CSS 缓存验证策略，再移除这些资源的手动版本号；素材保留缓存策略，测试用重新导入参数保留。
3. 集中跨模块事件名，提供支持局部根节点的 DOM 工具，页面固定节点使用语义名称映射。
4. 抽离首页、结果弹窗、三关控制器及存档协调；游戏控制器拥有共享流程，各关控制器拥有棋盘状态；模块导入无初始化副作用，实例支持清理监听与计时器。
5. 抽公共 HTTP 请求函数，认证保留 AuthError/字段/204/用户校验，论坛保留 Retry-After/账号隔离，挑战保留轮次/快照/冻结负载。公共传输层不自动重试。
6. 完成受影响的单元与真实浏览器验收，更新项目目录树、部署说明及实施报告。

## 状态与依赖边界

- main.js 仅创建和启动应用；首页只展示入口并报告选择。
- game-controller 管理账号、当前关卡、共享计时、请求状态、服务端轮次验证和通关协调。
- mine/sudoku/akari-controller 管理对应棋盘，通过 canPlay/onChange/onComplete 等显式回调连接共享流程。
- progress.js 保持存档格式校验和序列化；progress-coordinator 注入快照读写方法，协调保存，避免反向导入所有控制器。
- result-dialog 管理展示、按钮和焦点；业务请求由游戏控制器决定。
- 各关互不导入；避免可被任意模块写入的全局状态容器。

## 测试与交付规则

新增模块接口先写契约测试并观察失败，再实现。已有行为测试持续保护原有断言；测试通过创建新应用实例模拟刷新，避免依赖子模块重复求值。
每阶段只运行受影响测试，最终执行一次完整前端测试及相关浏览器脚本。输出写入 artifacts 日志，只读取失败摘要或最终统计。
关键回归：三关独立进入与重开、首次确认起计时、规则/离开期间累计、通关冻结、刷新与浏览器重启恢复、数独笔记、账号与轮次隔离、网络失败同负载重试、爆炸清理、跨页登录/论坛/榜单/通知。
每阶段通过后中文提交；保持存档和 API 兼容以支持代码回退。部署时成套替换前端文件并核验响应头，考虑旧强缓存过渡。
