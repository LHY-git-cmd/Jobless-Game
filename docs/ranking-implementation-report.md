# 排行榜与逐关挑战实施报告

日期：2026-10-18

状态：已完成本地实现与自动化、浏览器验收；未执行真实 MySQL/Flyway 迁移或服务器部署，目标规格资源验收待完成。

## 实际行为

- 每轮只能从扫雷开始，通关并保存成功后进入照明，再进入数独。首页后续入口锁定，后端也校验本轮前序关卡。
- 每关通关立即保存，保存失败保留终盘并可重试，成功前不解锁下一关。重试复用尝试标识和原始秒数。
- 三关总榜只取同一轮完整通关的最好总时长，不组合跨轮次单项最佳；单游戏榜展示每位玩家对应游戏的历史最佳。
- 四榜均按整数秒升序，同秒并列为 1、1、3，同分按达成时间与用户 ID 稳定排序；每页 20 人，接口最多每页 50 人。
- 每人每个游戏和完整一轮分别保留最佳与最近三次的并集。最佳在最近三次内时去重，每类最多四条，四类合计最多十六条已完成记录。
- 总成绩保存该轮三项用时快照；即使单项旧记录已清理，仍可展开原轮次明细。
- 每个账号维护一个当前轮次，新开一轮使旧轮次失效。返回首页和换号清空浏览器本轮状态，历史已保存成绩保留；不恢复进行中的棋盘。
- 完整一轮成绩冻结后不能重开其中一关改写该轮总成绩；页面提示返回首页开启新轮次。

## 数据与接口

迁移文件：[V2__create_ranking_tables.sql](../backend/migrations/V2__create_ranking_tables.sql)。V1 未修改，应用启动不自动建表。

| 新增表 | 用途 | 保留边界 |
| --- | --- | --- |
| challenge_progress | 当前轮次、版本、固定三关尝试及已接收状态 | 每个账号一行 |
| completion_records | 单游戏与整轮的不可变成绩快照 | 每人每类最佳与最近三次的并集 |
| leaderboard_entries | 每人每榜的最佳引用与排序摘要 | 每人每类一行 |

沿用五层架构。Controller 处理同源、Cookie、严格 DTO 和公开响应；Service 管理认证、顺序及事务；Repository 封装 SQL。写入先锁用户，再锁定读取进度、最佳与最近记录，避免 MySQL 默认隔离下等待锁后仍使用旧快照。最佳更新与清理同事务提交，失败整体回滚。

公开查询先按复合索引读取有限页，再统计比该行更快的玩家数计算名次，避免持久化名次或物化全榜窗口。新增写接口纳入现有 4KiB 实际请求体限制，复用有界数据库线程和连接池，无新增常驻服务、逐秒提交或排行榜自动轮询。

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/challenges/config | 开发通关开关 |
| POST /api/challenges/start | 幂等创建本轮 |
| POST /api/challenges/{run_id}/restart | 版本校验与本轮当前关重开 |
| POST /api/challenges/{run_id}/complete | 单关保存并在三关完成后生成总成绩 |
| GET /api/rankings/{category} | 四榜公开分页 |
| GET /api/records/me?category=total | 当前登录用户的最佳与最近三次 |

## 页面与开发验收按钮

四个独立入口为 `frontend/ranking.html`、`ranking-mine.html`、`ranking-akari.html`、`ranking-sudoku.html`，共用查询和渲染脚本。沿用海岛背景、深蓝与暖金、系统中文字体；用户名用 textContent 渲染。提供空榜、加载失败重试、分页、键盘导航与总榜可展开明细。

开发按钮集中于 `frontend/src/dev-quick-complete.js` 和 main 中的开发入口，仅完成当前关的合法终盘，继续经过正常冻结计时、保存、解锁和结算。没有首次操作时点击验收按钮从此刻起计时，整数秒可能为 0，不伪造未完成值。

在专用开发数据库配置 `DEV_QUICK_COMPLETE_ENABLED=true` 并重启后端后显示按钮；默认关闭，配置读取失败时保持隐藏。关闭时后端拒绝专用开发标记。正式配置保持 false，验收数据不导入正式库。后续移除步骤见 [后端说明](../backend/README.md#排行榜与挑战)。
