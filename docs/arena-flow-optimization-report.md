# 竞技棋盘与对局流程优化报告

日期：2026-10-27（北京时间）。用户已确认方案并明确“开始执行”。本轮仅实现现有三游戏竞技优化，未部署生产或迁移业务数据库。

## 最终行为

- 保留竞技难度，配置来自当前正式闯关目录：扫雷简单10×10/10雷、照明第10关、数独简单9×9。双方同题同版本，新局保存冻结快照；照明用旋转/镜像、数独用数字双射换题，避免紧邻两局初始题面相同。
- 棋盘复用闯关CSS、素材和游戏规则。扫雷先选格，再标记/排雷；照明保留亮格、灯泡和约束反馈；数独支持数字键盘、笔记、撤回、清除、关联格与冲突高亮、键盘操作。数独笔记和最近100步撤回按账号/局保存在同一浏览器。
- 匹配/邀请成功后仍在大厅等待双方准备，统一3秒倒计时结束后跳转独立pk-game页面。刷新恢复同一局，不重置题目或时钟。
- 服务端结算后双方显示原生弹窗，说明胜负/超时/平局、用时和积分。十分钟双方未完成明确为平局，积分不变，用时固定为10:00。重复通知不叠加弹窗，也不重复结算。
- “返回房间”保留仍在场的双方，调用者不自动准备；“再战”确认本人后回到准备房间，等待原对手确认。双方确认后倒计时进入新局。两人可以分别从结果弹窗或房间准备，不要求同时关闭弹窗。
- 每局使用独立room_id与唯一后继链接，旧结果、提交、积分流水不可变。结算后的席位最多保留5分钟，断线30秒回收，主动离开即释放，继续遵循原有4房容量。

## 关键实现与修复

V21为pk_rooms增加lobby_expires_at、索引及next_room_id，不修改旧迁移。新增POST continuation接口，以统一业务锁、用户锁和持久化后继指针保证双方并发及重复请求只创建一局。

独立游戏页固定读取URL中的原局，因此对手先返回或确认再战不会让本人跳过旧局结算。离开页后拒绝迟到快照写回，避免旧结果重新覆盖本地当前房间；已离开成员的空扫雷快照也能正常显示历史结果。

跨页恢复可能与公共账号读取抢占现有4个执行槽，竞技读取遇到503最多重试三次。竞技会话恢复可向共享账号模块注入该读取方式，其他页面默认行为不变；首次入页同步确认幂等在线租约，避免大厅已可操作但搜索结果仍显示离线。业务写请求不自动重放。SSE被409/503拒绝后主动退避重建，页面销毁或换号后清理旧流与定时器。

手机棋盘直接复用闯关素材，修正棋盘自身44px默认变量覆盖缩放值的问题。游戏页压缩重复提示和操作区，提供可见焦点、数字按钮名称与原生dialog焦点约束。

## 2026-10-27追加：双方点击准备仍未准备

用户反馈按钮可点击，但仍未准备或提示“状态已更新”。在隔离真实Nginx开启application/json gzip时复现：响应ETag被代理改成W/"版本号"，竞技前端将它原样作为If-Match提交，服务端强修订校验返回412。旧的412重试仍带弱标签，再次失败；紧接着刷新房间还会覆盖错误说明。

修复仅涉及前端flow.js和page.js：从每次GET快照核对安全整数revision与强/弱ETag完全对应后，生成房间接口约定的强修订条件。准备、取消准备、真实412后的有限重试以及好友房模式条件写均走相同核验；不存在或不一致的版本不发起写请求。没有放宽服务端校验，也不对未知弱标签直接去掉W/。并发准备仍重放本人原意图，已经准备或进入倒计时就不再写入，连续真实冲突继续报告失败。

TDD先观察新增测试失败，再通过真实Nginx确认旧版无法准备。修复后前端全量200项通过；开启gzip的双Chrome完整5组竞技场景通过，包含弱ETag、准备/取消、双方倒计时跨页、再战、三棋盘及超时结果；额外断言原样弱If-Match仍被后端拒绝。日志为artifacts/frontend/arena-ready-frontend-final.log及arena-ready-browser-final.log。

此修复无需SQL迁移、API镜像重建或重启；已部署本轮竞技页面的站点只需同步两个前端文件并强制刷新。本地验证不代表正式网站已经覆盖成功，仍需核对线上实际模块及双账号操作。
