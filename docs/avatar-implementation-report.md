# 预设头像实施报告

日期：2026-10-20。实施范围按用户最新确认：001 至 025 共25张，覆盖各页现有账号入口、游戏设置及四个排行榜。实现位于 `codex/preset-avatars` 分支。

## 实际行为

- 新老账号默认使用001。进入游戏设置，展开头像列表，选择后点击“保存头像”；失败保留原头像和选择，允许重试。
- 头像编号保存在账号中，刷新、跨页和独立浏览器重新登录可恢复。声音偏好仍只保存在当前浏览器。
- 四榜显示账号当前头像；同页更换立即更新头像，不改变成绩、排序或分页，也不触发换号事件或清空棋局。
- 退出清理头像预览，旧账号晚到响应被丢弃。加载失败可重试，图片失败仅回退默认图一次，默认图也失败时使用固定尺寸占位。
- 选择项支持键盘按钮操作；模态窗口保留 Tab 循环和 Esc 焦点恢复。桌面五列、手机四列、320px窄屏三列，触控按钮至少44px。

## 硬盘、内存和部署

开发机脚本 `source/imge/prepare_avatars.py` 保留原始 PNG，生成128×128、WebP质量参数82的成品；25张图片共 **104680字节，约102.2KiB**，清单另占少量空间。已检查联系表及桌面、390px和320px实际页面截图。

成品保存在服务器硬盘的 `frontend/assets/avatars/v1/`，由现有 Nginx 提供；所有用户共用25个文件。Python仅缓存有效编号，不将图片载入业务缓存，不新增常驻服务或生产图片处理依赖。Pillow仅用于开发机转换。

`users.avatar_id` 为 `TINYINT UNSIGNED NOT NULL DEFAULT 1`，每人编号原始数据1字节，不包括数据库行、页和备份等开销。浏览器按128×128×4字节估算，全部25张解码像素约1.56MiB，另有浏览器开销；服务器实际内存和目标机器峰值尚未测量。

新增 `PUT /api/auth/avatar`，只接受当前Cookie账号的严格整数清单编号；拒绝额外字段、伪造user_id、跨站及超过4KiB的实际请求体。复用现有四个数据库执行槽和连接池。登录、/me和榜单响应增加avatar_id；榜单沿用已有用户关联查询，未新增逐用户查询或修改历史快照。

前后端共用catalog.json，图片内容更新时更换资源版本路径；本次同步更新入口脚本和CSS版本，避免旧资源缓存。现有离线打包和Docker构建已包含静态目录与迁移文件，无需改动打包代码或服务拓扑。

发布步骤：备份 → Flyway执行V3并核对无Pending → 更新后端 → 发布前端。MySQL5.7不依赖CHECK验证头像，校验由应用执行；ALTER锁表时间须在目标库评估。旧版应用回退可保留新增列。
