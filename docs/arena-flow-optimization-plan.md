# 竞技棋盘与对局流程优化计划

日期：2026-10-26（北京时间）。2026-10-27更新：用户已明确“开始执行”，实施与本地验证记录见arena-flow-optimization-report.md。

## 已确认范围

本轮仅优化竞技现有的扫雷、照明、数独。

- 保留原竞技难度：扫雷10×10、10雷；照明约闯关第10关；数独简单9×9。
- 复用对应闯关的棋盘配置、样式和操作方式，不增加竞技难度或尺寸选择。
- 匹配或邀请成功后留在房间准备；双方准备并结束3秒倒计时后，跳转独立游戏页面。
- 任意一方获胜或比赛到时，由服务端结算，双方展示结果弹窗。
- 弹窗提供“再战”和“返回房间”。再战与原对手换题，双方确认后开始；返回房间保留双方，允许重新准备。

## 现状与问题

竞技使用独立题池和简化的formal-board视图，闯关已有专门的棋盘样式与交互。竞技扫雷是点格直接揭开，闯关是选格后执行标记或排雷；竞技数独缺少闯关已有的数字键盘、笔记、撤回与关联格提示。

目前开局只是滚动到大厅下方棋盘，结果只是页内文字。结算时立即释放双方房间占用，也没有同一对手的续局资源，增加两个按钮无法完整实现返回房间与再战。

## 技术选型声明

沿用原生HTML/CSS/JavaScript、FastAPI、MySQL、Flyway、HTTP写入与SSE状态通知，不增加框架或常驻服务。

最高优先级建议：先统一棋盘配置来源并保障每局结果和积分不可变，再实现页面跳转及续局交互。闯关的体力、经验和星级结算属于闯关会话，不接入竞技会话；竞技继续由服务端验证终盘和判定胜负。

需要持久化的续局关系和确认状态通过新增Flyway迁移实现。当前最高版本为V20，实施前复核版本后从下一版本追加，不修改已执行迁移。

## 设计与执行步骤

### 1. 统一三种棋盘

- 扫雷配置来自当前闯关“简单·10×10”。复用选格、标记、排雷、键盘操作及棋盘适配。双方共享隐藏雷区和统一安全起点，保留竞技公平开局及踩雷立即判负。
- 照明以当前发布的闯关第10关配置为基准，复用墙格、灯泡、照亮反馈、约束提示和自适应布局。续局通过保持规则与解的变换生成同难度题目。
- 数独使用当前发布的简单题配置，复用选格、数字键盘、笔记、撤回、清除、键盘操作和冲突提示。结合简单题池及保解变换换题。
- 优先抽取或复用必要的展示与输入逻辑，避免复制整套闯关控制器。保留闯关原有功能和存档兼容性。
- 同局双方使用同题同版本；再战避免立即重复上一局的初始题面。服务端保存当局题目快照，刷新不会换题。

### 2. 独立游戏页面

- 新增竞技游戏HTML页面及对应pages入口；大厅保留邀请、匹配、模式选择、双方准备及倒计时。
- 只在权威房间状态进入playing后跳转，URL携带房间标识。直达链接及刷新均先校验身份、成员关系和房间状态。
- 独立页展示三种游戏对应棋盘、双方状态、统一比赛时间和退出操作，保留账号与站点视觉风格。
- 复用服务器时间锚点和SSE通知；页面跳转后恢复本人草稿与已揭格，不重新开局。过期链接返回相应结果或当前房间。
- 对局中页面隐藏或刷新不暂停比赛。主动退出沿用判负确认；浏览器返回大厅时根据权威状态恢复当前对局，不能绕过退出规则。

### 3. 结果弹窗

- 根据服务端结果展示胜利、失败、平局、超时或作废的说明，以及本局用时、积分变化和余额。
- 结果弹窗按单局标识管理，SSE重连或重复刷新不会叠加弹窗、重复加扣积分。
- 使用原生dialog，提供可见焦点和明确按钮；结束后棋盘不能继续操作。
- 到时显示“时间结束”；双方均未完成沿用平局不变分。保留当前合法完成1秒平局窗口、退出判负、断线宽限等已确认规则。

### 4. 返回房间和再战

- 保留已结束对局的结果、提交和积分流水，新一局通过持久化关系关联上一局，不覆盖旧结果。
- 正常结算后保留仍在房间的双方席位；明确退出、房间到期或失联清理时释放占用，并沿用容量边界。
- “返回房间”进入双方仍在的准备房间，本人不自动准备。
- “再战”记录本人续局确认；对手尚未确认时显示等待，不能单方面启动新比赛。对手点击再战或在房间准备均可完成本人确认。
- 双方确认后更换题目、清空新局草稿和准备状态所需的旧局信息，按统一3秒倒计时再次跳转游戏页。
- 双击、丢响应重试、双方同时操作只能建立一局续局；对手已经离开或不再可用时明确提示，不能强行拉入。
- 处理一方仍看结果、一方已返回房间的状态同步，确保双方都能看到上一局结算，之后进入同一续局房间。

### 5. TDD与验证

先补充以下有意义的失败测试，观察失败后再实现对应功能。测试输出写入artifacts，只报告失败摘要或最终统计。

- 后端：闯关配置同源、双方同题、扫雷答案隐藏、终盘验证、到时结算和积分幂等。
- 后端：保留成员、再战双方确认、并发续局唯一性、旧结果保留、退出与失联释放、其他房间占用冲突及刷新恢复。
- 前端：开局跳转时机、刷新恢复、胜负与超时弹窗、再战与返回房间状态、过期响应及账号切换隔离。
- 棋盘：扫雷选格与操作、数独笔记/撤回/键盘及照明反馈；复用部分运行相应闯关回归测试。
- 双浏览器：匹配/邀请→准备→倒计时→跳转→胜负或超时→再战或返回房间的完整流程；检查320/375像素及桌面布局。
- 如增加数据库结构，验证真实MySQL/Flyway迁移及相关事务；不可用时如实记录待验收项，不用模拟数据库结果代替。

## 交付与边界

交付范围为相关代码、增量迁移、测试、必要的项目目录树更新及验证记录。通过验证后按功能使用中文描述提交。

不增加新竞技游戏、难度选择、奖励系统或匹配算法，不部署生产或迁移业务数据库。服务器资源约束继续遵循README-CONSTRAINTS.md。

实施顺序：配置和棋盘复用 → 续局与幂等接口 → 独立页面与弹窗 → 联调验证 → 中文功能提交。
