## 已实现内容

- 论坛列表及可直接访问的 `forum-post.html?id=编号` 详情页；文字主题、顶层评论、回复评论或已有回复，始终保持两层展示。
- 游客公开浏览，Cookie 会话决定发布身份；复用现有用户名和预设头像。只填正文发布，文字通过 textContent 展示，保留换行；正文2000、评论/回复500个 Unicode 码点，两端统一去首尾空白。
- 主题及评论 UUID 请求幂等；失败重试冻结原编号和原负载。先确认幂等，再检查可配置的60秒发帖和3秒评论/回复间隔，频率拒绝附 Retry-After。
- 帖子、评论及回复分别点赞/取消；PUT/DELETE 明确设置状态，联合主键限制重复，内容行锁保护计数，请求期间禁用相应按钮，服务端确认成功后更新。
- 用户→帖子→评论锁顺序；创建内容、计数和通知在同一事务内提交，通知失败整体回滚。服务层不处理 HTTP，Repository 不提交，认证和同步 SQL 在已有四槽执行器内完成。
- 全站账号入口及三个游戏界面共用一个消息控制器。自己互动不提醒，回复只提醒直接目标作者；首次点赞固定事件键去重，取消/重新点赞不追加通知或重置已读。
- 消息、计数与已读按账号持久化；打开消息面板不会全部已读，点击标记单条并定位，全部已读使用此次列表 through_id 边界。未读查询最多100条，前端超过99显示99+。
- 登录且页面可见时轻量查询未读；请求结束后再安排60秒下一次，隐藏和退出停止，可见性切换有冷却，过载按 Retry-After 及指数退避。轮询计数不重新构建消息列表，避免移除键盘焦点。
- 身份换代同时隔离晚到的成功和失败响应；注销使未完成身份检查失效，清空旧账号发布状态和私人消息，公开内容按新身份重新读取。
- 帖子/消息倒序游标、顶层评论/回复正序游标，默认20/20/10、最多50。查询一次关联当前作者、头像和当前账号点赞；通知直接取目标与根上下文，后续页目标也能定位。
- 原生模态、显式输入标签、标准按钮/链接、焦点恢复、加载/空列表/失败/重试状态、手机布局和论坛返回位置恢复（最多恢复前五页）。游戏跳转复用原有棋局保存。

## 数据库与接口

新增 `V4__create_forum_tables.sql`，包含 `forum_posts`、`forum_comments`、`forum_post_likes`、`forum_comment_likes`、`forum_notifications`。V1～V3 未修改，应用不自动建表。纠正计划中用户主键类型的概括：现有 users.id 是 INT UNSIGNED，所有用户外键与其一致；论坛内容编号为 BIGINT UNSIGNED。SQL 使用 InnoDB、utf8mb4、UTC DATETIME(6)，不依赖窗口函数或 CHECK。

全部接口均在 `/api/forum/`：

| 接口 | 行为 |
| --- | --- |
| GET /posts、POST /posts | 主题摘要游标页、幂等发布 |
| GET /posts/{id} | 主题全文 |
| GET/POST /posts/{id}/comments | 顶层评论游标页、幂等评论/回复 |
| GET /comments/{id}/replies | 根评论下回复游标页 |
| GET /posts/{post_id}/comments/{comment_id} | 目标及根评论上下文、同帖校验 |
| PUT/DELETE /posts/{id}/like、/comments/{id}/like | 三类内容点赞/取消 |
| GET /notifications/unread-count、/notifications | 自己的有限未读数、消息页及边界 |
| PUT /notifications/{id}/read | 幂等标记自己的单条已读 |
| POST /notifications/read-all | 按 through_id 标记已有消息已读 |

未登录写入401，同源失败403，对象缺失404，关联/幂等冲突409，输入422，发布频率429，执行器/数据库繁忙503。论坛写请求单独32KiB，应用按实际接收字节在 JSON 解析前检查，普通及分块请求均覆盖；登录、头像、挑战仍4KiB。本地 Docker 与宝塔 Nginx 模板已同步，线上配置未修改。
