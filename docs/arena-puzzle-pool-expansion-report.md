# 竞技独立题库扩充与近期去重实施报告

日期：2026-10-27（北京时间）。按已确认计划实现照明、数独各20道独立原题，并避开双方账号在该游戏中各自最近4局的原题。未连接或部署业务服务器。

## 题库与难度

新冻结版本为backend/content/arena-puzzles-v2.json，每种游戏20个稳定base_puzzle_id；旧v1内容及历史房间快照保持。保留原有照明第10关底题和3道简单数独，新增19道独立照明与17道独立数独，不以旋转、镜像或换数字充数。

照明全部10×10、唯一解、与原第10关相同的tier=1逻辑层级，审计推理步数36～47，基准39步。20种墙体拓扑在八种方向规范化后各不相同。数独全部9×9、25个给定数字、唯一解且按原分级器为easy；不仅数字/方向规范化后不同，20题的行/列/宫线索数量不变量也各不相同，可以排除合法行列重排和数字替换的复制题。

backend/arena_content.py只在开发机离线构造和审核，固定种子并限制构造次数；已存在冻结文件时拒绝覆盖。arena-audit-v2.json保存生成来源、推理轨迹及唯一性审核。产品请求不导入生成器、不进行在线求解，不下发答案或审计轨迹。同档逻辑指标不能代替真人用时校准。

## 去重与事务

V22新增arena_puzzle_history，以(user_id,game_id)为主键，每行最多4条原题/房间记录。两种游戏分别记录；账号删除时级联清理，不关联可清理的房间外键，不随历史房间回收丢失，不产生无限增长的去重流水。

最终双方准备完成时重新读取双方近期原题并集，避免只按创建者或旧对手选题。20题最多被两人各4条排除8题，正常至少有12题可选；展示变换仍使用相同原题ID。倒计时进入playing时与房间状态在同一事务写入双方记录，失败全部回滚；房间记录标记和局ID共同防止重复维护重复追加。准备前取消与取消倒计时不记历史，已开局后退出/超时计入。

房间冻结原题ID、题库版本及实际题面；双方同题，GET、刷新或重连不重新抽题。原题ID与题库版本只在playing/finished下发，等待和倒计时不提前发题。旧局没有新身份字段时保持旧快照和原终盘校验，不补写不可靠历史；V22上线前已经看过的题不会自动反推近期记录。

扫雷产品逻辑、闯关定义、时限、自动提交、积分及准备修复不变。全量回归中发现原有扫雷测试夹具可能把末格随机放成两颗同坐标雷，导致偶发误报首击安全失败；只修正夹具构造，未修改扫雷产品代码。
