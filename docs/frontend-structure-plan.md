最高优先级：先恢复可靠测试基线，再做机械迁移。当前118项测试117通过，唯一失败为历史completion测试从当前首页提取已下线节点；应改为明确的历史HTML夹具，保留原断言而非跳过。18个从现有HTML不可达的JS仅是遗留候选，不能凭静态可达性删除；本次移到标明用途的legacy目录，保留历史存档兼容和对应测试。

## 执行步骤

1. 从已存在的历史Git版本取出旧首页作为非发布测试夹具，修复测试对当前index.html的错误依赖，观察基线转绿；中文提交。
2. 编写结构及资源引用契约并先观察失败：全部当前HTML入口统一到src/pages、src/shared无业务反向依赖、当前入口不加载legacy、相对JS/CSS/素材引用有效、CSS拆分顺序不变、测试夹具不进入容器发布。新增目录迁移工具注明用途，路径解析拒绝越界。
3. 保留当前HTML地址，迁移JS到pages、features、games、shared、legacy；抽出请求ID和时间格式化等真正公共能力，避免论坛依赖排行榜和新页面依赖旧游戏会话。legacy仅保存旧单关/九关练习实现，不自动启用旧入口。
4. 样式移到styles，先按原规则顺序分段，保留层叠顺序和语义色；移动文件同时修正CSS图片URL、JS new URL资源和HTML链接。测试按模块归档，历史测试从固定夹具读DOM；改写仍用于当前功能的验收脚本路径。旧缓存探测路径保留小型兼容入口。
5. 核对Docker上下文白名单、镜像/发布包复制与静态缓存策略；新增styles目录必须能被打包。更新README、目录树及整改报告。
6. 完整前端及相关静态服务测试、当前扫雷/暂停/星级/手机、论坛/账号/榜单与竞速入口浏览器检查。重构前后同状态渲染比对；不修改业务数据库或生产部署。按功能中文提交并交付预览。
