# 10点体力上限与通关返还修复

日期：2026-10-26（北京时间）。用户要求把体力上限提高到10，并修复通关不返还的问题。

## 当前规则

- 账号共用上限10，新创建的体力记录初始10；已有余额不重置、不直接补满。
- 每30分钟恢复1点，原有未满恢复节点保留，满10点停止累计。原来满5点且没有恢复节点的旧账号，在新规则下首次读取时开始恢复至10的周期。
- 普通开局扣1点，成功通关返还本局实际支付的1点，每局一次，最多10点。
- 教学不扣不返；失败、主动退出、旧局无扣费凭证不返。重开另扣1点，体力不足不丢弃原局。
- 前端按服务器返回的capacity展示，并接受滚动更新期间的历史5点快照，但不允许旧修订覆盖新余额。

## 根因与技术选型

生产数据库Session设置autoflush=False，Repository读取使用populate_existing=True。原refund方法修改了体力余额和返还凭证，但尚未flush。结算随后生成体力快照时再次读取相同余额行，待写的加1和修订号被数据库旧值覆盖；返还凭证却仍可能提交为已返还，因此看起来完成了结算却没有实际增加体力。

原部分隔离测试使用默认autoflush=True，查询自动写入，掩盖了生产配置差异。本轮先将生产配置写入回归用例，实际观察到扫雷、数独、照明三种结算均漏返，再实施修复。

最高优先级是保证余额与返还凭证在同一结算事务中真正写入。refund末尾执行flush，不单独commit；后续奖励或快照失败时，体力、凭证和成绩仍一起回滚。保留现有账号行锁、上限及防重规则，不新增服务或后台任务。

## 数据库与发布

- 新增V20__increase_energy_default_to_ten.sql，仅把player_energy.current的数据库默认值设置为10；V15及其他已执行迁移保持原样。
- V20不更新任何旧余额、恢复节点或返还凭证，不自动补发历史漏返。历史补偿需要另行按真实扣返数据核对，本轮不据旧标记批量发放。
- 上线需先备份并执行V20，再同步更新API镜像与前端energy.js。仅覆盖前端不能修复数据库返还事务，也不能提高后端上限。
- 现有v1.0标签保留原版本含义，本轮修改需另行发布；此记录不代表远程服务器或本机8080已经更新。
