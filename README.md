# 无职游戏

远程仓库：[LHY-git-cmd/Jobless-Game](https://github.com/LHY-git-cmd/Jobless-Game)。

手机端优先的三关网页游戏。入口采用海岛背景与关卡素材，棋盘和弹窗使用统一的深蓝、暖金色界面。

设计、开发与部署前请阅读 [项目硬约束](./README-CONSTRAINTS.md)，其中明确了 2 核、2GB 内存与宝塔共存的资源边界，以及后续登录功能的账号、迁移和验收要求。

完整目录结构与文件夹用途见 [项目目录树](./PROJECT-TREE.md)。后续目录结构、所列文件或用途变更时，必须同步更新该文档。

后端按控制层、业务层、数据访问层、模型层和公共层组织，调用方向为 Controller → Service → Repository。层级职责和扩展约定见 [后端架构说明](./backend/README.md#五层架构)。

顶部导航按“排行榜 / 无职游戏 / 论坛”排列。排行榜只提供扫雷、照明、数独三个独立分榜，原排行榜入口默认展示扫雷分榜。文字论坛只填写正文即可发布帖子，支持评论、评论下回复及各自点赞；游客可读，登录后参与，复用游戏账号和头像。

帖子左下角评论数可点击，在卡片下方展开评论；右下角为拇指点赞和回复图标，点赞后显示红色。列表可直接回复帖子或他人评论，无需进入详情；评论和回复按需分页，收起再展开保留已加载内容。卡片间距已缩小，图标按钮仍保留44px点击面积。

同帖正文和展开评论共用一个连续容器。列表同时只显示一个两行回复框，在输入框右侧点击纸飞机发送；切换帖子保留草稿，原来的计数、取消和底部发送栏已移除。

主帖头像比评论大4px，作者和正文比评论大3px。列表单帖最高720px并适配视口，过多评论在帖内滚动，输入框保留在滚动区外；深层回复只用横线分隔，去掉重复卡片和额外缩进。

登录后全站铃铛显示站内互动提醒，游戏中也可主动打开。消息按账号保存已读，点击可直接定位讨论，全部已读保留之后到达的新消息。登录且页面可见时每60秒检查一次未读数，隐藏页面或退出时停止。上线前须先执行 Flyway V4 并合并独立的 `/api/forum/` 32KiB Nginx 配置。实际测试与环境限制见 [论坛实施报告](./docs/forum-implementation-report.md)。

- 第一关：10 × 10 扫雷，10 颗雷。进入游戏时显示规则弹窗，先点选格子，再按“标记”或“排雷”。
  踩雷后按距离依次显示、引爆全部地雷，播放裁剪后的爆炸音效；连锁结束再显示结果。可关闭音效，重新开始或返回首页会停止动画与声音。音效从 `source/audio/爆炸声.flac` 的 0.045～1.445 秒裁剪，保留起爆与短尾音并淡出，处理脚本为 `source/audio/prepare_explosion.py`。
- 第二关：固定题盘照明，10 × 10 格、唯一解。点击白格放灯，再次点击撤灯，照亮全部白格且满足数字黑格即可通关。手机上可在棋盘区域滑动。
- 第三关：固定题盘数独，34 个已给数字、唯一解。进入数独时显示规则弹窗，可点格填数、记录候选数笔记、清除和检查进度。点击“笔记”切换模式，开启时点击 1–9 添加或取消候选数，在空格内按 3×3 小数字显示；关闭后输入正式答案，并清除本格笔记。数字键盘同样遵循当前模式，清除按钮擦除选中格的答案或笔记。笔记不参与冲突和通关判断，不自动填入或排除候选数；刷新、退出和返回首页后保留笔记与模式，重开数独时清空。旧存档恢复时补充空白笔记，保留已有答案和计时。

扫雷、照明、数独三个关卡直接开放，可按任意顺序独立挑战。首页卡片按当前账号存档显示“开始游戏”“继续游戏”或“已通关”。点击进行中的关卡继续原棋盘和计时，点击已通关关卡查看结果；主动重新开始只重置当前关，其他关卡的棋盘、笔记和用时保持原样。刷新后仍恢复当前账号进度。未登录时先打开登录弹窗，成功后进入所选关卡的规则弹窗。用户名不存在时自动创建账号，已有账号必须验证原密码。各页右上角提供登录、用户名和退出入口，刷新或跨页可恢复登录会话；棋局按账号保存在当前浏览器，游戏逻辑仍在浏览器执行。服务端继续使用一个当前进度容器管理三个独立尝试。

各关进入或重新开始时先显示规则，点击“开始游戏”立即计时，无需等待棋盘操作。首次阅读规则不计时；开始后可点击“规则”重新查看，窗口显示期间计时继续，点击“继续游戏”或按 Esc 返回棋盘不会重置起点。通关后用时冻结。每关通关立即保存，保存失败时保留终盘和原请求负载，允许重试。保存成功后点击“查看本关结算”只展示本关用时，并可打开对应分榜。取消整轮用时汇总；结算返回首页保留全部关卡进度，三关全部完成后仍可分别查看或重开。

首页介绍下方始终显示“选择你的挑战”，点击滚动到关卡卡片，不清除任何关卡进度。首次进入任意关卡时创建挑战进度，创建失败后重试复用同一个请求编号。

游戏每次操作后按账号自动保存到当前浏览器的本地存储。刷新、关闭标签页或浏览器后，同一账号再次打开游戏自动恢复棋盘；误点返回首页后，点击开始按钮继续原局。已开始的关卡保留原始计时起点，离开页面及首页停留期间继续累计；未开始的关卡不提前计时，通关或扫雷失败后的用时保持冻结。恢复时通过 `GET /api/challenges/{run_id}` 核对服务端轮次，网络失败保留存档并可重试，通关和重开请求保留原幂等标识。存档仅在同一浏览器可用，清理本站数据会删除棋局；禁用本地存储时页面会提示无法保存。

三个分榜分别使用对应游戏的历史最短通关时长，同秒并列（1、1、3）。每位玩家的每个游戏保留“最佳＋最近三次”的并集，每类最多四条，重合时去重。分榜公开浏览，每页 20 人。三关总榜和整轮个人记录接口停用，不再生成整轮成绩；既有数据库字段和历史记录保留，不需要修改已执行的迁移或清理历史数据。早期表结构与实施背景见 [排行榜计划](./docs/ranking-implementation-plan.md) 和 [实施报告](./docs/ranking-implementation-report.md)，当前行为以本文为准。

首页介绍区右侧提供“我的通关记录”窗口，手机上位于介绍下方。登录后可切换扫雷、照明、数独，查看自己的最佳及最近三次用时和通关时间，默认显示扫雷。通关保存后自动刷新，也可手动刷新。未登录时可从窗口打开登录，退出或换号立即清空旧账号记录，读取失败可重试。

开发阶段可在**专用开发数据库**环境设置 `DEV_QUICK_COMPLETE_ENABLED=true` 并重启后端，启用各关“开发验收：一键通关”。按钮只完成当前关，随后按正常保存和单关结算流程验收。默认关闭；正式环境保持 `false`，测试记录不导入正式库。该功能集中在 `frontend/src/dev-quick-complete.js` 及对应配置/标记处理，便于后续移除。

登录后点击右上角的用户名按钮打开“游戏设置”，分别控制背景音乐、音效的开关和 0–100% 音量。默认均开启，背景音量默认 28%，音效默认 65%；调节立即生效并保存在当前浏览器，刷新或切页后保持。扫雷页面音效按钮与设置同步；左下角不再显示音乐开关。音效包括扫雷爆炸声和结算胜利音；关闭背景音乐不影响音效，关闭音效也不影响背景音乐。任意关卡成功保存后，点击“查看本关结算”播放 `frontend/assets/audio/victory.mp3`，来自用户提供的 `花亦落心亦冷 - PVZ胜利音效.mp3`；连续重复打开同一次尝试的结算不重播，关闭结算或返回首页停止，关闭音效时不补放。浏览器禁止自动播放时，等待用户点击或键盘操作后重试，隐藏页面暂停播放。

游戏设置还可从25张预设头像中选择并点击“保存头像”，新老账号默认001。头像跟随账号保存，刷新、跨页或换浏览器登录后保持；各页账号入口和三个单关排行榜显示当前头像。所有用户共用服务器硬盘上的25张128px WebP，合计约102.2KiB，数据库只保存编号。开发机可运行 `python source/imge/prepare_avatars.py --preview` 重新生成成品及联系表，需要 Pillow；生产后端无需图片处理依赖。上线前须先执行 Flyway V3。实现、验收结果与环境限制见 [头像实施报告](./docs/avatar-implementation-report.md)。

背景音乐使用用户后续提供的 `backmusic-墨澜音 - 阿尔法脑波音乐 (记忆力提升).mp3`，网页资源为 `frontend/assets/audio/background.mp3`，按设置音量循环播放。首次进入可能需要点击或键盘操作后开始，胜利音播放期间暂停背景，音效结束或关闭结算后在背景开关开启时从原位置恢复。页间跳转保存播放位置；多文档跳转可能短暂停顿，下一页仍受浏览器自动播放规则限制。原始 NCM 不作为网页资源。

## 本地预览

完整登录运行方式见 [后端运行与部署](./backend/README.md)：配置 MySQL、执行 Flyway 后，在项目根目录运行 `python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8001 --workers 1 --limit-concurrency 32`，打开 `http://127.0.0.1:8001/`。Python 依赖与环境示例位于 `backend/`。

只预览静态页面时，仍可在 `frontend` 目录运行 `python -m http.server 8000`，但静态服务器没有登录 API，不能完成真实登录或进入需要登录的关卡。

## 测试

在 `frontend` 目录运行 `npm test`。测试使用 Node.js 内置测试工具，不需安装依赖。

后端使用 `python -m unittest discover -s backend/tests -v`。真实 MySQL/Flyway 测试需单独配置专用测试库，否则明确跳过；当前登录、独立关卡、单关结算与排行榜浏览器验收使用 `python artifacts/frontend/verify_ranking.py`；论坛双账号、消息及手机布局验收使用 `python artifacts/frontend/verify_forum.py`，账号只写临时数据库。完整测试输出应写入日志。

## 版本管理

`.gitignore` 排除敏感本地配置、密钥、虚拟环境、依赖、缓存、日志及浏览器验证生成物。源码、网页素材、测试和 `artifacts/frontend/verify_*.py` 验证脚本纳入版本管理。脱敏配置模板可使用 `.env.example` 等示例文件名提交；后续 Flyway SQL 迁移文件也应提交。

## 部署

服务器已安装宝塔 Nginx/MySQL 时，可使用 [宝塔服务器快速部署](./backend/deploy/server/README.md)：在开发机生成离线 ZIP，服务器导入 API/Flyway 镜像，交互填写数据库凭据后单次迁移并启动后端。前端由宝塔提供，后端只监听本机；无域名时先用公网 IP 的 HTTP 临时验收，正式使用需配置 HTTPS。

本机完整 Docker 验证（Nginx、FastAPI、MySQL 与一次性 Flyway）已提供，入口为 `http://127.0.0.1:8080/`。首次准备 `.env.docker` 后运行 `docker compose --env-file .env.docker up -d --build --wait --wait-timeout 180`。配置、数据卷、资源限制与验证步骤见 [Docker 部署说明](./backend/deploy/docker/README.md)。该配置只绑定本机，不替代服务器 HTTPS 与资源验收。

Nginx 站点根目录指向 `frontend/`，使用 HTTPS 并将同源 `/api/` 转发到本机单进程 FastAPI；后端和真实配置放在 Web 根目录之外。Flyway 在维护窗口单次执行后退出。宝塔、Nginx、systemd 以及低资源配置模板位于 `backend/deploy/`，具体步骤见 [部署说明](./backend/README.md)。切换前备份原配置与文件，先验证后切换。
