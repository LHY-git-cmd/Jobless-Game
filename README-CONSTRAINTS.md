# 无职游戏：项目硬约束

更新日期：2026-10-18

本文用于约束本项目后续设计、开发、测试和部署。当前已实现功能见 [README](./README.md)，登录实施步骤见 [登录功能实施计划书](./docs/login-implementation-plan.md)。本文不是功能完成或服务器验收报告。

“必须”“不得”表示实施与验收要求；“初始值”“预算目标”表示需要实测的设计基线，不代表已测结果。用户后续明确修改要求时，同步更新本文与实施计划，避免规则不一致。

## 1. 服务器资源边界

- 目标服务器只有 **2 核 CPU、2GB 内存**。
- 同一台服务器运行 **宝塔面板及其他必要服务**。不得将整机资源全部分配给本项目。
- 实际资源分配必须以服务器的总内存、现有服务占用及可用内存为依据，不能直接套用开发电脑配置。
- 项目新增服务必须计入常驻内存、CPU、连接数和发布时的资源峰值。
- 在目标规格下，必须对请求、数据库连接、密码计算和等待队列设置边界，避免突发流量导致资源无限增长。
- 不得用增加 Swap 替代资源预算或以持续换页换取“可运行”；验收必须检查 OOM 和持续换页抖动。

## 2. 技术与部署约束

- 后端采用 **Python + FastAPI**，数据库采用 **MySQL**，数据库版本迁移采用 **Flyway**。
- 前端沿用现有 HTML、CSS、JavaScript。游戏棋盘逻辑与液态玻璃视觉效果在浏览器执行。
- 优先复用宝塔已有的 Nginx、MySQL 和服务管理能力；不得为本功能重复部署同类常驻服务。
- 生产环境默认使用 **一个 Uvicorn 工作进程**，关闭开发热重载；扩进程前必须重新验证整机资源预算。
- 登录与会话使用 MySQL；当前方案不引入 Redis、Celery 等额外常驻服务。
- 生产环境由 Nginx 提供静态页面与素材，并将同源 `/api/` 请求转发给后端。
- 现有其他服务共用 MySQL 时，不得直接按本项目需求降低全局连接上限或覆盖共享数据库配置。
- 构建、图片处理、依赖编译和压测负载生成优先在开发或构建机器完成；部署步骤必须考虑运行中服务的资源占用。

## 3. 登录与账号规则

- 游戏入口页、排行榜页和论坛页右上角提供登录入口。
- 未登录点击任一游戏关卡，必须先显示登录弹窗。登录成功后进入原先选择的关卡；取消弹窗不得开始游戏或计时。
- 从右上角登录成功后停留当前页面。
- 登录弹窗采用液态玻璃透明效果，并保证文字可读、手机端可用、键盘可操作。
- 用户名不存在时自动注册并登录；已存在时验证原密码。
- 同名账号密码错误时不得创建新账号、覆盖原密码或绕过验证。
- 用户名允许汉字、ASCII 英文字母和数字混合，不允许为空，不接受空白、标点或表情符号。
- **汉字计 1.5，英文字母和数字计 1，总计不得超过 12。** 前后端必须使用相同的 Unicode 字符计数规则；可等价采用汉字计 3、字母数字计 2、总计不超过 24 的整数算法。
- 用户名英文大小写视为相同。必须使用数据库唯一约束保证账号键唯一，覆盖并发首次注册场景。
- 密码至少 **6 个字符**；密码区分大小写，不自动删除用户输入的空格。
- 必须保存密码哈希，不保存或记录明文密码；前端不得保存密码以维持登录。
- 登录状态由服务端验证，不能仅根据前端变量或本地存储认定登录成功。

## 4. 会话与接口资源约束

- 使用 Argon2id 密码哈希，必须显式配置参数和计算并发上限；校验、新用户哈希、自动重哈希都受同一限制。
- 密码计算和同步数据库访问不得阻塞异步事件循环；执行线程及等待请求必须有边界。
- 登录入口必须具备可配置的限流、请求体大小限制和明确的超时/繁忙响应，前端必须允许用户重试。
- 数据库连接池必须有上限、有限等待时间，并在请求结束后释放连接。
- 会话使用 HttpOnly、SameSite Cookie；正式 HTTPS 环境启用 Secure。数据库保存随机会话凭据摘要及到期时间。
- 退出登录必须使当前会话失效；过期会话必须分批清理，避免大事务和无索引扫描。
- 配置和示例文件不得包含真实密码、会话凭据或其他秘密；日志不得泄露这些内容。
- 前端不得每秒轮询登录状态；游戏计时不得产生逐秒后端请求。

## 5. Flyway 迁移约束

- 建表及后续结构变更通过版本化 SQL 迁移管理，不依赖 ORM 启动时自动创建或修改生产表。
- 已执行的迁移文件不得直接修改；后续变更新增迁移版本。
- Flyway 只在发布或维护阶段执行，执行完成后退出，不作为常驻服务。
- 迁移必须针对明确配置的项目数据库执行；连接凭据通过环境配置提供。
- 发布前必须核算 Flyway 与运行中服务叠加的资源峰值；内存不足时安排维护窗口，先停止本项目后端再迁移。
- JVM 堆上限不等于 Flyway 总进程内存，必须检查实际峰值。

## 6. 初始参数与预算目标

下表来自当前实施计划，供首次配置和压测使用。**参数尚未在目标服务器验证，实施计划也尚待确认；这些数值不是容量承诺或全部不可变的硬上限。** 调整时必须保留前述资源边界并记录依据。

| 配置项 | 初始值或目标 |
| --- | --- |
| Uvicorn 工作进程 | 1 |
| Uvicorn 并发连接/任务保护阈值 | 32，超限返回 503；不代表在线人数 |
| 数据库连接池 | `pool_size=3`、`max_overflow=0`、等待超时 3 秒 |
| MySQL InnoDB 缓存 | 256MiB，仅为缓存，不是 MySQL 总内存 |
| 独立项目 MySQL 实例连接数 | 20；共享实例须先核算其他服务需求 |
| Argon2id | `memory_cost=65536` KiB、`time_cost=3`、`parallelism=1` |
| 同时执行的登录计算流程 | 1 |
| 登录接口按 IP 限流 | 每分钟 5 次、突发额度 5；需验证共享出口场景 |
| 登录请求体 | 最大 4KiB |
| 会话有效期 | 7 天，可配置 |
| 系统、宝塔及其他必要服务 | 400–650MiB 预算目标，不重复计入下列服务 |
| MySQL 全进程 | 450–600MiB 预算目标 |
| Python 全进程及受限密码计算 | 200–300MiB 预算目标 |
| Nginx | 20–50MiB 预算目标 |
| 运行余量 | 尽量保留至少 350MiB 可用内存 |

如果现有服务占用或实测峰值超出预算，必须先调整设计与配置，再进行资源验收。不能将上述预算目标写成“实际只占用这些内存”。

## 7. 验收与开发流程

- 必须检查现有三个游戏的规则弹窗、计时、关卡切换和结算是否受登录接入影响。
- 必须验证用户名边界、大小写同名、自动注册、错误密码、并发同名注册、会话恢复及退出。
- 必须验证突发登录下的并发限制、限流、数据库超时，以及普通会话查询的可用性。
- 真实 MySQL 与 Flyway 的联调必须单独验证；其他数据库或模拟结果不能替代这一验收。
- 资源验收必须记录服务器本底占用、运行峰值、CPU、可用内存、数据库连接数、登录延迟及过载响应；不得根据桌面机测试承诺生产在线人数。
- 无法访问目标规格服务器时，必须在报告中标注资源与容量验收待完成，不能标记为通过。
- 依照本聊天提供的 AGENTS.md：大工程先完成需求、设计与计划书确认；每完成一个模块展示产出，并询问“是否继续下一模块？还是需要调整当前方向？”
- 新增脚本必须注释作用；方法和关键逻辑提供必要注释。测试输出写入日志，对话只返回失败摘要或最终统计，避免重复运行未受后续修改影响的相同测试。
- 项目结构变更必须同步维护 [项目目录树](./PROJECT-TREE.md)：新增、删除、移动或重命名目录及所列文件、调整用途时，在同一次变更中更新树图、用途注释和日期；临时截图、日志、缓存等按文档规定合并列示。
- 当前任务边界为登录、首次自动注册及对应交互；排行榜和论坛内容继续保持占位，新增功能需有对应用户需求。
